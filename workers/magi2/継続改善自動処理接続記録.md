# 継続改善 A6・自動処理の接続

実装済み（2026-10-23）。正本はコード。本人の「自動処理の残りの実装を実施して」に従い、マージ→デプロイ→公開確認と、失敗時の復旧・停止・通知を接続した。基点は`f8d1dff7`。本番実行・段階変更・レビュー省略は行っていない。

## 実装

| 対象 | 内容 |
| --- | --- |
| マージ | main側でリポジトリ変数・PR・停止・head/base・正式レビューを再取得。最終headを指定してGitHubのrebase mergeを行い、APIが返したSHAのコミット内容と検証した差分を照合。結果不明や範囲違いなら公開せず停止 |
| 公開前 | 文書だけならWorker公開を省略。対象SHAを固定し、本番の版と未公開の手修正・dirty・モデル設定を確認。別の読み取り専用ジョブでWorkerの共通検査を行う |
| 公開と確認 | 既存の`deploy-worker-core.yml`と`magi2-daily-publication.yml`を再利用。前の版ID・対象SHA・出した版IDを引き継ぐ。PRコードの検査ジョブから採用するのは成否のみ |
| 復旧 | 公開した版IDを確定でき、現在もその版である時だけrollback。停止Issue保存後にも版を再取得。復旧版のID/SHAを確認してから独立したGitでdailyだけを新しい順にrevertし、trusted側の`push-with-retry.sh`でpush |
| 保持するもの | botの人格カード更新と、対象SHA後の本人コミット。競合はresetで解消しない。pushの認証は子プロセスの一時設定だけで、URL・git設定ファイルに保存しない |
| 停止と通知 | 失敗・割り込み・復旧成功のいずれも停止Issueを維持。対象SHA・版ID・戻すコミット・各操作の成否と残作業を記録。固定Issueとメールは独立して試し、メール成功後だけ通知済みを記録。通知失敗もジョブ失敗にし、停止を残す |
| 証跡 | 成否・IDだけの公開確認・復旧artifactを7日保存。カタログ・利用者本文・キー・APIの生応答は保存しない |

`magi2-daily-review-source.mjs`は正式サービスの取得口だが、現在は未設定を返す。PRコメントや転載JSON、環境変数のreadyを読み込む迂回口は用意していない。段階2の値だけでは動かず、この取得口の実接続と正式記録・最終headの合格が必要。

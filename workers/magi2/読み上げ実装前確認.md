## §0.1 Fish Audio の文書と規約

- **文書**: [fishaudio/docs](https://github.com/fishaudio/docs) の `6536c059`（2026-10-22）で、設計§1.3 の表が正しいことを確かめた。直すところは無い。
- **誤りの応答**（`api-reference/openapi.json`）: `POST /v1/tts` は 401（権限なし）・402（支払いなし）・503（高負荷）を `{ status, message, reason }` の JSON で返す。同時実行の上限は 429 で `Retry-After` なし（料金と上限の文書）。
  無料版の公正利用の超過がどれで返るかは書かれていない。設計§5.4 の通知は 401・402 を対象にし、429 は送り直しの後のエラー、503 はそのままエラーにする。超過の形は §0.2 の後に本人の問い合わせの答えで決める。
- **`GET /model/{id}`** は 200・403・404 を返す。403 は非公開のモデルを他人が読んだとき。
- **規約・プライバシーポリシー**: `fish.audio/terms`・`fish.audio/privacy` をこの環境から開けなかった。Web 検索で見えた第三者のレビューは、次のように書いている（一次資料ではないので、設計の根拠にはしない）。
  - 利用規約は、利用データとコンテンツをモデルの開発・学習に使えるとしていて、断る方法が無い。
  - 保存期間の定めは無く、送った内容を保存しない取り決め（Zero Data Retention）は Enterprise の契約だけ。
  - 公式のプライバシーポリシーのページは 2024-08-28 付。
  これが正しければ、🔊 を押した回答の本文が Fish Audio の学習に使われうる。設計§8 の `PRIVACY` の段落に書く必要があり、C1b の前に本人が一次資料を読んで確かめる（計画§3.4 の条件）。
- **サポートへの問い合わせ**（無料版の公正利用の目安と、超えたときの応答）: 未実施。本人のアカウントから問い合わせる。

## §0.2 声のモデルと無料版の応答

`.github/scripts/probe-magi-speech.mjs` を用意した。本人の PC で次のように動かす。

```bash
FISH_AUDIO_API_KEY=... node .github/scripts/probe-magi-speech.mjs all
```

- `model`: `GET /model/c9eb5405fa784e61ae9b3b22621e9f6f` の状態・公開の別・題名・言語。
- `tts`: 日本語 113文字・276文字、英語 261文字、日本語 113文字のくり返しを1回ずつ（`s2.1-pro-free`、mp3 64kbps、`latency: balanced`）。最初のバイトまでの時間・全体の時間・バイト数を記録する。4 区切り。
- `errors`: 誤ったキー（台帳に数えない）と存在しない声（1 区切り）の応答の形。
- モデルは `s2.1-pro-free` 以外を送らない。計画の上限 60 区切りを `workers/.wrangler/magi2-speech/ledger.json` で数え、送る前に予約し、超える要求は送らない。結果と mp3 は同じ場所の `probe-<時刻>/` に置く（Git 管理外）。
- この環境では、キーが無いときに送らずに止まることだけを確かめた。

## §0.4 長さの分布

保存済みの回答（Git 管理外の評価の記録・本人の端末の履歴）はこの環境に無く、分布は出せていない。分かっていることだけ書く。

- 通常の回答は統合人格に 200文字前後を指定している（`personas.js`）。本番の公開確認の実回答は 101・86・94文字だった（[先行改修公開2評価](先行改修公開2評価.md)）。設計§5.1 の区切りで 1〜2 区切りになり、IP ごと 30 区切りで1日に 15回以上読める。
- Web で確かめた回答は 4,000文字を超えることがある（[A2修正公開評価](A2修正公開評価.md)）。設計§5.3 の 3,000文字の上限で 11 区切りになり、IP ごと 30 区切りでは1日に2回半。計画§0.4 の「90% の長さの回答を3回」を満たすかは、Web の回答の割合と長さの分布次第で、未確認。
- 出典のアイコン: 1件 6KiB 以下・最大5件なので、Web の回答1件あたり最大 30KiB 増える。Web（トップページ・PWA）の localStorage の上限はおよそ 5MB で、保存会話の件数への影響は保存済みの履歴で計算する（未実施）。
- 本人の PC で、保存済みの回答から分布を出す。`speechText` を実装した後に、同じ関数で区切りを数える。

## §0.5 Cloudflare

[cloudflare-docs](https://github.com/cloudflare/cloudflare-docs) の `ef319319`（2026-10-22）の Workers の文書で確かめた。

| 項目 | 内容 | 設計への影響 |
| --- | --- | --- |
| WebSocket の1メッセージ | Worker が受けるメッセージは 32MiB まで（超えると 1009 で閉じる） | チャットの要求（最大 12MiB）は WebSocket の最初のメッセージに入る。設計§6.2 の「画像付きは SSE」は不要 |
| 相手の Close への返答 | `compatibility_date` が 2026-04-07 より前は、Worker が自分で `close()` を返す必要がある（magi2 は 2025-01-01） | 測定の入口では返している。C2 の入口でも返す |
| 接続の時間 | HTTP の要求に時間の上限は無く、相手がつながっている間は続く。ランタイムの更新時は WebSocket・SSE に 20分の猶予 | 討議の最長（約250秒）に問題なし |
| CPU 時間 | 有料プランは既定 30秒・最大 5分。外部の応答を待つ時間は数えない | 今の SSE と同じ。magi2 のプランは有料と推定（未確認） |
| `ctx.waitUntil` | 応答を返した後・相手が切った後も 30秒まで | 読み上げの区切りのキャッシュへの書き込み（設計§5.4 の段7）は、応答を流し終えた直後に行えば収まる |
| Cache API | 独自ドメインの route（`workers.tk.st`）で使える。データセンターの間で複製されない。1オブジェクト 512MB。chunked の応答を `put` すると、終わるまで次の `put` が待つ。呼び出しは外部への要求の数（有料 1,000）と共有 | 1区切りの音声は数十KB で問題なし。キャッシュが効くのは同じデータセンターから再生したときだけ |
| 同時の接続 | 応答の見出しを待っている接続は1要求あたり6つまで（外向きの WebSocket を含む）。7つ目は待たされる | 出典のアイコンの取得（最大5件）は本文の取得と重なると待たされる。設計§4.4 の 3秒の期限の中で、取れなかった分は頭文字の丸にする |

## §0.6 WebSocket の測定

- `workers/magi2/probe.js` に設計§6.5 の一時の測定を実装し、`src/index.js` の入口の先頭につないだ。`wrangler.toml` の `PROBE_ENABLED="true"` のときだけ動く。AI・D1・secret を使わない。
  - `GET /magi2/probe`: 測定のページ（noindex）。［開始］で SSE と WebSocket を同時に 60秒受け、開けたか・件数・最初の受信・間隔の最大・遅れの最大・最後まで届いたかと、判定を表示する。結果はどこにも送らない。
  - `GET /magi2/probe/sse`・`/magi2/probe/ws`: 2秒ごとに番号と Worker の時刻を送る。SSE はチャットと同じ 2KiB の最初の合図と見出しを付ける。測定のページの Origin（`https://workers.tk.st`、手元は loopback）か Referer の GET だけを受け、isolate ごとに同時6本まで。
- `test-magi2.mjs` に、無効なら 404、ページ・Origin と Referer の検査・`Upgrade` の無い WebSocket の 426・SSE の最初の合図、AI を呼ばないことのテストを足した。全 304 件が成功。`wrangler deploy --dry-run` も成功。
- 手元の `wrangler dev` と Chromium で、測定のページを2通りで開いた（それぞれ 60秒）。

| 経路 | SSE | WebSocket | 判定の表示 |
| --- | --- | --- | --- |
| 直結 | 30件、最初 2.1秒、間隔の最大 2.0秒 | 30件、間隔の最大 2.0秒 | SSE は少しずつ届いている（WebSocket は不要） |
| SSE だけ溜め、WebSocket は素通しにする手元の中継 | 30件、最初 60.1秒（全部まとめて） | 30件、間隔の最大 2.0秒 | WebSocket に効果あり |

- 残り: 本番の Worker へのデプロイ（本人の承認が要る）と、本人の会社の PC（Chrome・Comet 各2回）と自宅（Chrome 1回）での測定。開くのは `https://workers.tk.st/magi2/probe`。測定が済んだら `probe.js`・入口・`PROBE_ENABLED` を外して出し直し、`/magi2/probe` が 404 になることを確かめる。

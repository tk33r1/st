# ニュース採否のJev判定とブランド名の救済

実装済み（2026-10-04）。正本はコード。

国内・海外のRSSニュース候補に、Jevの採否基準付きyes/no質問1問を適用する。
質問と基準は `.github/scripts/daily_news_filter.py` の `POLICIES['nitori']` が正本。
見出し・RSSの説明・配信元を渡し、採用境界は0.5。記事全文は補完しない。

JevでNGになった記事でも、見出しまたはRSS説明に「ニトリ」「島忠」「デコホーム」「N+」
を含む場合は、後段の記事選定に渡す候補に戻す。海外向けの `NITORI` も対象にし、
英字の大小と全角表記 `N＋` を揃える。配信元の名前だけでは救済しない。
救済は候補を残す処理で、記事の最終採用を確定しない。

処理順はRSS取得 → 既掲載・URL重複の除外 → 日付確認 → Jev判定とブランド名救済 →
候補内の見出し重複の除外 → 並べ替え → 従来のAIによる記事選定・要約。
候補にJev採用・従来ルール採用・ブランド名救済の区別を保持し、この順で優先する。
重複する見出しや後段AIの件数上限では、救済候補がJev採用記事を押し出さないようにする。
検索の `-レシピ`・`-スイーツ` を外し、商品使用の記事を内容判定前に消さない。
一般検索のブランド条件には `N+`・`N＋` も加える。

ブランド名で戻した候補には、投資推奨・同名別物・別事業への言及だけの記事も入り得る。
後段AIの選定基準には、ブランド名だけで採用せず商品・店舗・事業の具体的な情報を確認し、
投資推奨や数字だけの決算などを除くことを明記する。
後段AIが失敗してルールベース発行に切り替わった場合、ブランド名救済の候補は掲載しない。
除外は発行件数を絞る前に行い、Jev採用・従来ルール採用の候補と既存のSNS枠を残す。
救済件数と、障害時に従来ルールを使った件数をログに出す。

API障害・不正応答は当該記事だけ従来ルールで判定する。キー未設定・モデル設定の失敗も
従来ルールへ戻し、その場合はブランド名で判定結果を上書きしない。
キーは既存の `TYPESAFE_API_KEY`、手元の `MAGI_TYPESAFE_API_KEY` または
`workers/magi2/.dev.vars` を読む。モデルは共通設定の正本を使う。
並列数4・タイムアウト8秒・障害通知はリテールテックと共通。

X・TikTokの追加ソースは既存のSNS採否判定を使い、ニュースの救済を適用しない。
外部通信なしの確認は `.github/scripts/test-daily-news.py`、週次のAPI確認は
`ai_models.py` の `smoke_typesafe` でニトリの出店・N＋・投資推奨・同名別物を確認する。

救済案の比較結果は [ニュース候補のブランド名救済の評価](news-rescue-evaluation.md) を参照。
その評価は提示された4語での結果で、本実装で追加した英語・全角表記を含む精度の再測定ではない。

# マサラテトリス TIFFIN ― 企画書

> `masala-tetris-vindaloo` の続編。シリーズ4作目。
> VINDALOO は「全部入り」の最大主義だった。TIFFIN はその逆を行く **引き算の続編**。
> ルールは1画面で説明でき、AI は敵ではなく**相棒**になる。

---

## 0. 確定した方針

| 項目 | 決定 |
|---|---|
| タイトル | **マサラテトリス TIFFIN**（ティフィン＝インドの多段弁当箱） |
| コンセプト | **一段ずつ、丁寧に。** ふつうに気持ちいいテトリス ＋ 一捻り（オーダー制）＋ AI相棒 |
| VINDALOO からの継承 | **なし**（コードは新規。世界観とワーカーAPIだけ共有） |
| AI の役割 | **味方／コーチ**（VINDALOOの「敵AI・実況AI」からの明確な反転） |
| モード | **1つだけ**（エンドレス）。モード選択画面を作らない |
| 難易度 | **選択させない**（レベルで自然に上がる） |
| LLM | **DeepSeek V4 Flash**（`deepseek-v4-flash`）。既存ワーカー `st-games-api.tk33r1.workers.dev` に `POST /api/deepseek` を新設して使う。**1プレイ2回** |
| 実装形態 | 単一 HTML（Tailwind CDN + Canvas 2D + Web Audio 合成サウンド） |
| 想定規模 | 60〜70KB 程度（VINDALOO は 119KB。**半分**を目標にする） |

## 1. なぜ「引き算」なのか

VINDALOO は役システム・ローグライト・商人・レリック・VERSUS・LLM実況を全部積んだ。作品としては野心作だが、**始めるまでに覚えることが多く、1プレイが重い**。シリーズの天井はもう「盛る」方向にはない。

TIFFIN の勝ち筋は逆側にある:

1. **30秒で理解でき、3分で1プレイ終わる。** 通勤中に開ける重さ。
2. **一捻りは1つだけ。**「オーダー（注文）」。役テーブルもレリックもショップも無い。
3. **AI が初心者の味方になる。** テトリスの最大の壁は「どこに置けばいいか分からない」。そこを AI が直接埋める。これは実況ではできなかったこと。

**世界観のメタファー**: ムンバイの弁当配達人＝**ダッバーワーラー**。手書きの記号だけで1日20万食を誤配率ほぼゼロで届ける、世界一正確な配達組織。「正確に運ぶ AI」の擬人化としてこれ以上ない題材で、しかも**ティフィン（多段弁当箱）は段を積み重ねる容器**＝テトリスそのもの。

## 2. コアループ

```
ピースを置く ──▶ ライン消去
                  │
                  ├─▶ オーダー達成 ──▶ ティフィンが1段積まれる
                  │                        │
                  │                        └─ 3段たまる ──▶ 配達完了！
                  │                                           ・スコア倍率アップ
                  │                                           ・レベルアップ（少し速く）
                  │                                           ・ヒント +1 回復
                  └─▶ 次のオーダーが1件だけ提示される
```

画面に出ている情報は常に **「今の注文 1件」と「ティフィンの段数（0〜3）」だけ**。これがルール説明のすべて。

## 3. コアシステム詳細

### 3.1 オーダー（注文）― 唯一の一捻り

盤面上部に**常に1件だけ**注文票が出る。達成したら次の1件が出る。それだけ。

| 注文 | 条件 | ねらい |
|---|---|---|
| 二段弁当 | 2ライン同時消し ×1 | 「揃えてから消す」を覚えさせる |
| 三段ティフィン | 3ライン同時消し ×1 | 我慢の練習 |
| 特急便 | 20秒以内にライン消去 ×3 | 速度側に振る回 |
| 右端まで配達 | 最右列を含むライン消去 ×2 | 端の処理を意識させる |
| きれいに詰めて | 穴を作らずに6ピース設置 | 丁寧さを評価する |
| マサラ増し | Tミノでライン消去×2（T-spinなら一発で達成） | 上級者へのご褒美。ただし詰まりどころにしない |
| おかわり | 連続で2回ライン消去（REN） | テンポを作る |

- 注文は**達成できなくてもペナルティなし**。放置してもゲームは進む。焦らせない。
- ただし達成しないとティフィンは積まれず、スコア倍率も上がらない。
- 注文の抽選は現在の盤面の高さを見て軽く調整（盤面が高い時に「三段ティフィン」を出さない、程度）。

### 3.2 ティフィンと配達

- オーダー1件達成 = ティフィン 1段（弁当箱の絵が1段積み上がる演出）。
- **3段で配達完了**。ダッバーワーラーが自転車で走り去るショートカット演出（1.5秒）。
- 配達完了ごとに:
  - スコア倍率 +0.5（×1.0 → ×1.5 → ×2.0 …上限なし）
  - 落下速度が1段階アップ
  - ヒント +1 回復（最大5）

倍率が青天井なので、**長く生き残るほど1ラインの価値が跳ね上がる**。これがスコアアタックの緊張感になる。

### 3.3 AI相棒「ダッバーの目」― 本作のAIの主役

**ローカル盤面評価AI**が、現在のピースの最善設置位置を**銀色のゴースト**で教えてくれる。ボタン1つ、3秒表示。

```
現在ピースの「全回転 × 全X位置」を列挙
 → 仮置き盤面を4指標で評価
    ・穴の数（最重視）
    ・全体の高さ
    ・凸凹（bumpiness）
    ・消せるライン数
 → 最高評価の位置を銀ゴーストで描画
```
- 完全ローカル。**API不要・遅延ゼロ・コストゼロ・オフラインでも動く。**
- 初期3回。配達完了ごとに +1 回復（最大5）。

**そしてここが設計の肝**: ヒントを使うと、そのプレイの**「手仕事ボーナス」倍率が下がる**。

| ヒント使用回数（累計） | 手仕事ボーナス |
|---|---|
| 0回 | ×1.5 |
| 1回 | ×1.3 |
| 2回 | ×1.15 |
| 3回以上 | ×1.0 |

→ 初心者は遠慮なく使って「どこに置くのが正解か」を学べる。上級者は**使わないことがスコアになる**。同じ1つの機能が、両方の層に別々の意味を持つ。ここが「シンプルだけど楽しい」の核心。

### 3.4 標準テトリスの手触り（ここはケチらない）

シンプル＝機能が少ない、ではない。**操作の気持ちよさは全部入れる**。ここを削るとただの劣化版になる。

- SRS 準拠の回転＋壁蹴り
- 7-bag ランダマイザ
- ホールド（1枠）、ゴーストピース
- ハードドロップ／ソフトドロップ
- T-spin 判定、REN
- NEXT は 3個表示

## 4. LLM の使い方（1プレイ2回）

VINDALOO の4回から**2回に削る**。多いほど良いものではない。

### ① 開始時：「本日のご注文」

```
本日のご注文 ── ダッバーワーラーより
「昼までに、三段の弁当を届けてくれ。雨季だ、急げ」
```

- **日付を seed にして生成し、localStorage に日付キーでキャッシュ**。同じ日は何度遊んでも同じ口上 → 「今日の分」という感覚が出て、API 呼び出しも1日1回で済む。
- 実際のゲームルールは変えない（**文章だけ**）。ルールを日替わりにすると「シンプル」が壊れる。

### ② 終了時：「配達報告書」

プレイ統計（総ライン数・最大同時消し・配達回数・ヒント使用回数・生存時間）を渡して、ダッバーワーラーが2行で講評する。

```
配達報告書
「12食お届け。三段は一度きりだが、穴は少なかった。
 明日はもう少し急いでいい」
                            配達評価 ★★☆
```

- 星（★☆〜★★★）は**ローカル計算**（LLM に判定させない＝ブレない）。文章だけ LLM。
- **この報告書がそのままシェア文になる**。X / LINE シェアで「AIに何て言われたか」が拡散のフックになる。

### 実装上の約束

- ワーカーに `POST /api/deepseek` を新設して使う（**DeepSeek V4 Flash**）。既存4ゲームが使う `/api/gemini` は触らない。
- **API キーはワーカーの secret**（`DEEPSEEK_API_KEY`）。公開HTMLであるゲーム側には絶対に置かない。
- クライアントが送るのは `{ prompt }` だけ。**モデル・`max_tokens`・thinking の可否はワーカー側で固定**する。Origin ヘッダはブラウザ外から偽装できるので、料金に響くパラメータを外に開けない。
- `thinking` は **disabled**。30〜50字の一言に推論は要らず、速さと安さを取る。
- **fetch 失敗時は必ずローカル定型文にフォールバック**。オフラインでもゲームは完全に成立する。
- 呼び出しは全て非同期。**LLM の応答をゲーム進行の待ち条件にしない**。
- フォールバック文は**キャッシュしない**（キー未設定や残高不足が直ったとき、翌日を待たず本物を取りに行けるように）。

## 5. 「入れないもの」リスト（この企画で最も重要な章）

続編は放っておくと肥大する。以下は **v1 で明示的に作らない**。

| 入れない | 理由 |
|---|---|
| 役テーブル（スパイス役） | VINDALOO の核。持ち込むと引き算にならない |
| ローグライト／商人／レリック | 1プレイが重くなる最大要因 |
| VERSUS（対戦） | AI を「味方」に反転させた本作と方向が真逆 |
| モード選択画面 | 起動から1タップでプレイに入りたい |
| 難易度選択 | レベル進行で足りる |
| 高頻度の LLM 実況 | 2回で十分。多いと読み飛ばされる |

「面白そうだから」で追加したくなったら、**代わりに何を削るか**を先に決める。

## 6. 演出 / サウンド / 見た目

VINDALOO は「激辛・赤黒・爆発」。TIFFIN は**その真逆の色温度**にして、シリーズ内で一目で区別できるようにする。

- **色**: ステンレスの銀 ＋ ターメリックの黄 ＋ テラコッタ。昼下がりの光。
- **背景**: マンダラではなく、弁当箱の布包み／自転車／ムンバイの路地の淡いシルエット。
- **サウンド**: Web Audio 合成。穏やかなラーガ＋タブラ。ライン消去は金属の弁当箱が「カチン」と噛み合う音。配達完了は自転車のベル。
- **演出は控えめに**。画面震え・大爆発はしない。ティフィンが1段積まれる時の小さな手応えと、配達完了の1.5秒だけに演出を集中させる。
- **フォント**: シリーズ踏襲（見出し Cinzel Decorative ＋ 本文 Noto Sans JP）。

## 7. レイアウト

- **PC**: 中央に盤面。左に NEXT / HOLD / ホールド、右に注文票・ティフィン段・スコア・ヒント残数。
- **スマホ**: 縦積み。上に注文票＋ティフィン、中央に盤面、下に固定タッチコントローラ（十字＋回転＋DROP＋**ヒントボタン**）。
- ブレークポイントは DX / VINDALOO と同じ 768px。**ヒントボタンは親指の届く位置に単独で置く**（本作の主役機能なので）。

## 8. 技術構成

- 単一 `game/masala-tetris-tiffin/index.html`。Tailwind CDN + Google Fonts + Font Awesome。
- Canvas 2D 描画。ブロックスケールはシリーズ踏襲（20px/block ベース、レスポンシブ倍率）。
- 状態は素の JS。`Board` / `Order` / `Tiffin` / `Advisor`(評価AI) / `Narrator`(LLM) の5つに関数分割。
- ランキングは `localStorage`（キー `tiffinRankings`）。モードが1つなのでキーも1つ。
- SEO / OGP / JSON-LD は DX・VINDALOO と同形式で `masala-tetris-tiffin` 用に整備。
- **付随タスク**: ゲーム一覧の実データは `data/game.json`（`game/index.html` 内の配列は通信失敗時のフォールバック）。ここに TIFFIN を追加する。

## 9. 実装ロードマップ

1. **基盤テトリス** ― SRS・7-bag・ホールド・ゴースト・ハードドロップ・T-spin・REN。ここだけで「気持ちいい」状態まで仕上げてから次へ進む。
2. **オーダー ＋ ティフィン** ― 注文7種・達成判定・3段配達・倍率。**ここでゲームが成立しているか一度止めて確認する。**
3. **ダッバーの目（評価AI）** ― 4指標評価・銀ゴースト・回数管理・手仕事ボーナス倍率。
4. **演出とサウンド** ― 配達演出・弁当箱SE・ラーガBGM。
5. **LLM 2箇所** ― 本日のご注文（日付キャッシュ）／配達報告書＋シェア。フォールバック必須。
6. **レスポンシブ ＋ SEO/OGP ＋ 一覧掲載**。

各段階で単一 HTML として動く状態を保つ。

## 10. 実装で確定したこと / まだ詰める点

### 実装時の設計変更（実測にもとづく）

**マサラ増しを「T-spin ×1」から変更した。** 実装後にヘッドレスで各注文の達成しやすさを測ったところ、T-spin だけは **12回中12回とも400ピース以内に未達**だった。理由は2つあり、どちらも本作の趣旨に反する:

1. T-spin は casual なプレイヤーにはまず出せない。ペナルティは無いが、注文は達成するまで居座るのでティフィンが積めず**進行が止まる**。
2. 評価AI は「真下に落とす手」しか提案しないので、**この注文だけ「ダッバーの目」が助けられない**。AI相棒が売りの作品で、最難関だけ相棒が無力になる。

→ **Tミノでライン消去×2、T-spin なら一発**の二段構えにした。上級者は即達成、それ以外も T を使えば進む。変更後の実測は 0/12 未達・平均37.3ピース。

### 実測した達成しやすさ（1件あたりの所要ピース数）

| 注文 | 平均 | 400ピース以内に未達 |
|---|---|---|
| きれいに詰めて | 6.7 | 0/12 |
| 特急便 | 11.1 | 0/12 |
| 二段弁当 | 14.1 | 0/12 |
| 右端まで配達 | 16.4 | 0/12 |
| おかわり | 20.7 | 0/12 |
| 三段ティフィン | 23.9 | 2/12（未達ではなく途中で天井到達） |
| マサラ増し | 37.3 | 0/12 |

配達1件 = 注文3件なので、体感の目標だった「1〜2分に1件」はおおむね満たしている。

### まだ詰める点

- 手仕事ボーナスの減衰カーブ（×1.5 → ×1.0）が上級者に厳しすぎないか。
- レベルごとの落下速度（初期900ms、配達ごとに-70ms、下限110ms）。
- 評価AI の重み。現状は穴を最重視（holes -0.95 / height -0.52 / bump -0.26 / lines +0.68 / well -0.12）の**やや保守的**な設定。推奨手だけで打たせると500ピースで約198ライン消せるので、実力は十分。

## 付録: タイトル代替案

TIFFIN を第一案として確定するが、参考まで:

| 案 | 意味 | 評価 |
|---|---|---|
| **TIFFIN** | 多段弁当箱 | ◎ 段を積む＝テトリス。ダッバーワーラー＝正確なAI。意味が二重に噛み合う |
| CHAI | チャイ | ○「激辛の次は一息」は伝わるが、積み上げの比喩がない |
| THALI | 定食皿 | △ 一皿に全部＝「全部入り」の含意で、引き算の続編に合わない |

# マサラテトリス TIFFIN ― 企画書 v2

> **「昼までに、届けろ。」**
> v1（実装・デプロイ済み）の作り直し。テトリス部分と世界観は残し、**ゲームの構造だけを入れ替える**。
> v1 は「丁寧に積む1人用パズル」だった。v2 は **90秒のアーケード**にする。

---

## 0. なぜ作り直すのか（v1 の失敗）

実際にデプロイして遊んだ結果は「**作業感が強く、ダラダラ続き、面白くない**」。
これは実装のバグではなく、**v1 企画書の設計判断そのものが原因**だった。原因は3つに絞れる。

### 失敗1: 「焦らせない」を美徳として設計してしまった

v1 企画書 §3.1 にこう書いてある：

> 注文は**達成できなくてもペナルティなし**。放置してもゲームは進む。焦らせない。

初心者に優しくするつもりだったが、**失うものが何も無いゲームは緊張しない**。
プレイヤーは「いつか達成できる」と分かっているので、ただ手を動かし続けるだけになる。これが作業感の正体。

### 失敗2: 最初の見せ場までが遠すぎる

v1 の実測（企画書 §10 の表）では、注文1件あたり **6.7〜37.3 ピース**。人間の手つきを 1.5〜2秒/ピースとすると1件で **15〜60秒**。
配達には**3件**必要なので、**最初の「配達完了！」までに1〜2分**かかる。

しかも v1 企画書はこれを「目標どおり」と書いて合格にしていた。**そこが判断ミス**だった。
起動して1〜2分、何のご褒美も無いまま積み続けるゲームを、今のプレイヤーは待ってくれない。

### 失敗3: エンドレスなので「終わり」の設計が無い

モードはエンドレス1つ。終わるのは自分がミスして積み上がった時だけ。
つまり **上手いほど長く、退屈に、遊ばされる**。1プレイの長さをゲーム側が一切コントロールしていなかった。

### 加えて、注文の半分が「作業」だった

「きれいに詰めて（穴を作らずに6ピース設置）」「右端まで配達」は、**判断ではなく指示への服従**を求めている。
面白い注文とは「いつ消すか / どこで消すかを迷わせるもの」であって、チェックリストではない。

## 1. v2 の方針

| 項目 | v1（失敗） | **v2** |
|---|---|---|
| 1プレイ | エンドレス（実質5分〜） | **90秒スタート。上手いと延びる** |
| 終わり方 | 積み上がるまで | **時間切れ**（＋積み上がり） |
| 注文 | 常に1件 / 制限なし / 罰なし | **常に2件同時 / 各々に制限時間 / 失敗は罰** |
| 配達に必要な注文数 | 3件 | **2件** |
| 上達の報酬 | スコア倍率 | **持ち時間そのもの** |
| ランダム性 | 無し | **「ムンバイの災難」で理不尽に殴る** |
| AI ヒントの対価 | スコア倍率が下がる | **持ち時間が減る**（一番痛い所で払わせる） |

**一言で言うと：時間を通貨にする。** スコアではなく秒を賭けさせれば、全ての判断が緊張する。

## 2. コアループ（v2）

```
     ┌──────────── 90秒のタイマーが常に減り続ける ────────────┐
     │                                                       │
     │   注文が常に2件、卓上に出ている（それぞれ制限時間つき）      │
     │        ↓ どちらを取る？ 片方を捨てる判断              │
     │   達成 → +3秒 ／ ティフィンが1段                       │
     │        ↓                                             │
     │   2段そろう → 配達！ +15秒 ・倍率アップ                │
     │                                                       │
     │   時間切れの注文 → −5秒 ・お邪魔1段 ・倍率リセット       │
     │                                                       │
     │   ときどき「ムンバイの災難」が理不尽に割り込む             │
     └───────────────────────────────────────────────────────┘
             0秒になったら終了。上手い人ほど長く走れる。
```

**最初の配達までの目標は 25〜35秒**（v1 は 1〜2分）。起動して30秒以内に一度は「配達完了！」を浴びせる。

## 3. 時間の設計（v2 の心臓部）

| 出来事 | 持ち時間 |
|---|---|
| ゲーム開始 | **90秒** |
| 注文1件 達成 | **+2秒** |
| **配達完了（2件達成）** | **+10秒** |
| 注文が時間切れ | **−5秒** |
| AIヒントを使う | **−3秒** |
| 残り10秒を切る | 画面が赤く脈打ち、BGMが速くなる |

- バッファ上限は **75秒**。
- スコアではなく秒を配ることで、「あと1件だけ…」という**延長への欲**が生まれる。これがアーケードの引き。

> **なぜスコアではなく時間か**：スコアは「終わったあとに分かる報酬」で、プレイ中の緊張には効かない。
> 時間は**今まさに減っているもの**なので、+10秒が体感でご褒美になる。v1 の倍率アップは、この点で無力だった。

### 「昼が迫る」── セッション長の唯一の保証

**時間の減る速さが、経過30秒ごとに +1倍される**（×1.0 → 30秒で×2.0 → 90秒で×4.0 → 上限×8.0）。
画面のタイマー下に `☀ 昼まで ×2.0` と常時表示し、危険域で色が変わる。

> **これは後付けではなく、実測で必要だと判明した中核機構。**
>
> 初版は「バッファ上限99秒」で貯め込みを防いだつもりだった。しかし評価AIに打たせて実測したら
> **1プレイ288秒・配達74件**。上限が縛るのは*バッファ*であって*セッション長*ではなかった。
> v1 の「上手いほど長く遊ばされる」失敗が、形を変えて再発していた。
>
> 計算すると原因は明快で、上手い人は注文を約2秒に1件こなすため、**注文ボーナスだけで +1.5秒/秒**入る。
> 一方ドレインは常に1秒/秒。**収入は腕前に比例し、支出は一定**。この形では延長量をいくら削っても、
> 十分上手い人の前では必ず発散する。
>
> したがって必要なのは数値調整ではなく、**腕前に依存しない収束装置**だった。
> 時間の減る速さ自体を経過時間で加速させれば、収入がいくら大きくても有限時間で必ず終わる。
> 「昼が近づくほど焦る」というテーマにも合致し、終盤の緊張を自動的に上げてくれる。

**必ず可視化すること。** 加速を隠すと、プレイヤーには「理不尽」ではなく「不具合」に見える。

## 4. 注文（v2）

**常に2件が卓上にある。** 片方を達成すると即座に新しい1件が補充される。

各注文には **12〜20秒の制限時間**（バーで表示）。切れたら失敗＝罰。
2件同時なので、**「こっちは間に合わない、捨てて向こうを取る」という判断**が常時発生する。これが v1 に決定的に欠けていた要素。

| 注文 | 条件 | 制限 | 何を迷わせるか |
|---|---|---|---|
| 二段弁当 | 2ライン同時消し | 18秒 | 積んで待つか、今消すか |
| 大盛り | 3ライン以上同時消し | 20秒 | もっと待てるか（欲張りの罠） |
| 特急便 | 8秒以内にライン消去2回 | 14秒 | 速度に全振り |
| おかわり | 2連続でライン消去 | 16秒 | テンポの維持 |
| 端まで配達 | 左右どちらかの端の列を使って消す | 16秒 | 置き場所の縛り |
| マサラ増し | Tミノでライン消去 | 16秒 | ミノ待ちのリスク |

**v1 から削除**：「きれいに詰めて（穴を作らずに6ピース）」──指示に従うだけの作業で、判断が無い。

- 盤面が高いときは「大盛り」を出さない（v1 の調整は維持）。
- 2件が同じ注文にはならない。

## 5. ムンバイの災難（理不尽さ）

**8〜14秒おきにランダムで発生。** これが v2 の「ハラハラ」の主成分。

| 災難 | 効果 | 持続 |
|---|---|---|
| 満員電車 | 下からお邪魔が1段せり上がる | 即時 |
| モンスーン | NEXT が見えなくなる | 4秒 |
| 牛が道を塞ぐ | 落下速度が2倍 | 5秒 |
| 伝票の取り違え | 進行中の注文1件が別物に差し替わる | 即時 |
| **特急ダイヤ** | 消去ラインと獲得秒数が2倍 | 8秒 |

### 理不尽の作法（守らないとただのクソゲーになる）

1. **必ず 1.5秒前に予告する。** 画面上部に災難名が出て、それから発動。
   → 回避はできないが**備えはできる**。この差が「悔しい」と「理不尽で萎える」を分ける。
2. **5個に1個は良い災難にする（特急ダイヤ）。** 予告が出た瞬間に「当たりか外れか」で心拍が上がる。全部罰だと予告がただの絶望通知になる。
3. **即死級は入れない。** お邪魔は1段まで。積み上がりで死ぬのは常にプレイヤーの手が原因、という納得を残す。
4. **残り10秒以内は災難を出さない。** 最後の見せ場を運で潰さない。

## 6. AI相棒「ダッバーの目」（v2 での役割変更）

機能そのもの（ローカル評価関数が最善手を銀のゴーストで示す）は **v1 のまま流用**。ここは実装済みで、質も測定済み（推奨手だけで500ピース中198ライン消去）。

**変えるのは対価。**

| | v1 | **v2** |
|---|---|---|
| 対価 | 手仕事ボーナス（スコア倍率）が下がる | **持ち時間 −3秒** |
| 回数 | 3回まで・配達で回復 | **無制限** |

v1 の「スコア倍率が下がる」は、プレイ中に痛みを感じない対価だった。だから初心者は使い、上級者は使わない、それだけ。

v2 では**一番貴重な資源である秒を払う**。
「詰みかけている。3秒払ってでも正解が見たい」──この判断そのものが緊張になる。回数制限を外していいのは、対価が十分痛いから。

## 7. 入れないもの（v2 で更新）

| 入れない | 理由 |
|---|---|
| **エンドレス** | v1 最大の失敗。1プレイの長さはゲーム側が握る |
| **ペナルティ無しの注文** | v1 第2の失敗。失うものが無いと緊張しない |
| 役テーブル / ローグライト / 商人 / レリック | 90秒に詰め込むには重すぎる |
| VERSUS | 別物になる |
| モード選択・難易度選択 | 起動から1タップで始めたい |
| 即死級の理不尽 | 悔しさは要るが、納得は残す |
| 時間の貯金（上限なし延長） | 上手い人が延々遊ぶのは v1 と同じ失敗 |

## 8. LLM（1プレイ最大2回 → **実質1.2回**に削減）

短いプレイを何度も繰り返す設計なので、**呼び出し回数がプレイ回数に比例して増える**。v1 のまま（毎回2回）だと20回遊べば40回叩くことになる。

| # | タイミング | 変更 |
|---|---|---|
| ① 本日のご注文 | タイトル | **v1 のまま**。日付キーで localStorage キャッシュ、**API は1日1回** |
| ② 配達報告書 | 終了時 | **配達2件以上、または自己ベスト更新の時だけ LLM を呼ぶ。** それ以外はローカル定型文 |

②の条件は演出としても正しい：**ダッバーワーラーは、ちゃんと働いた日にしか口を開かない**。
無言で終わった日の悔しさが、次の「あと1回」を作る。

技術面（`POST /api/deepseek` / DeepSeek V4 Flash / thinking 無効 / 失敗時は必ずローカル定型文 / フォールバックはキャッシュしない）は **v1 の実装をそのまま維持**。

## 9. 画面（v2 で変わる所）

- **タイマーを画面の主役にする。** 上部中央に大きく。残り10秒で赤く脈打つ。
- **注文票は2枚並べる。** PCは右サイドに縦2枚、スマホは上部に横2枚。各々に残り時間バー。
- **秒の増減を必ず飛ばす。** `+15s` `−5s` が数字ごとタイマーに吸い込まれる演出。**何で得して何で損したかが一目で分かる**ことが、この設計では最重要。
- **配達カットシーンは 1.5秒 → 0.5秒、かつ操作を止めない。** v1 の1.5秒停止は90秒中の1.7%を奪い、テンポも切る。
- ティフィンは3段 → **2段**。
- 世界観・配色・サウンド（ステンレス／ターメリック／テラコッタ、金属の弁当箱の音、ラーガ）は **v1 のまま**。BGM は残り10秒でテンポを上げる。

## 10. 流用と作り直しの切り分け

**そのまま使える（実装済み・検証済み）**

- テトリス基盤：SRS・壁蹴り・7-bag・ホールド・ゴースト・ハードドロップ・T-spin判定・REN・DAS/ARR
- 評価AI「ダッバーの目」（4指標・銀ゴースト表示）
- サウンド（Web Audio 合成）、レスポンシブ／タッチUI、ランキング、シェア
- LLM 連携（`/api/deepseek`・フォールバック・日付キャッシュ）

**作り直す**

- 時間システム（新規・v2の心臓）
- 注文：1件→2件同時、制限時間、失敗ペナルティ、「きれいに詰めて」削除
- 災難システム（新規）
- ヒントの対価：倍率 → 秒
- ティフィン 3段→2段、カットシーン 1.5秒→0.5秒
- HUD：タイマー主役化、秒の増減演出

テトリス部分が丸ごと生きるので、**作り直す範囲は実質ゲームルール層だけ**。

## 11. 実装後の実測（評価AIに人間相当の速度で打たせた結果）

| 指標 | v1 | v2 初版 | **v2 確定** | 合格ライン |
|---|---|---|---|---|
| 最初の配達まで | 60〜120秒 | 5.2秒 | **約6秒** | 40秒以内 |
| 1プレイの長さ | 実質エンドレス | 288.7秒 ✗ | **約114秒** | 200秒以内 |
| 終了理由 | 積み上がりのみ | 混在 | **3回とも時間切れ** | 時計が律速であること |

3回とも時間切れで終わる＝**時計がゲームを終わらせている**ということで、v2 の設計意図どおり。
評価AIは人間よりかなり強いので、実プレイはこれより短くなる見込み。

## 12. 数値は全部「仮」

90秒 / +15秒 / −5秒 / −3秒 / 12〜20秒 / 8〜14秒おき ── これらは机上の初期値であり、**遊んで決め直す前提**。

v1 の失敗は「実装後に自分で遊ばずに、AIの自動プレイ測定だけで合格にした」ことでもある。
v2 では **最初の配達までの秒数** と **1プレイの実測長** の2つを、必ず人間の手で測ってから確定する。

- 最初の配達までが40秒を超えるなら、注文の要求を緩めるか、配達に必要な注文を1件にする。
- 1プレイの平均が4分を超えるなら、延長量（+15秒）を削る。
- 「災難がうるさい」と感じたら、間隔を伸ばす前に**予告時間を伸ばす**。

## 変更

1. **ウィジェット用の本文と決議の集計を1つにした。** 受信中（`MagiConversationService.receive`）と保存済みSSEの読み直し（`MagiStreamStore.widgetData`）は、どちらも統合の`delta`をつなぎ、`verdict`の`tally`から決議を出していた。読み直しの側はレビュー修正3で増えたもの。この処理を`MagiWidgetData.Collector`へまとめ、両方から呼ぶ。`Run`の`widgetAnswer`・`widgetVerdict`も`widget`の1つにした。
   - 現在の動作は変えていない。受信中にウィジェットを書き換える条件は、これまでどおり本文が1文字でもあること（`hasText`）。完了の印`widgetAnswer`と読み直しの採否は、空白を除いて本文があること（`hasAnswer`）。統合の本文が空白だけのときに受信中だけウィジェットを書き換える違いは残している。揃えると動作が変わるため、今回は扱わない。
   - 値の取り出しはこれまでと同じCapacitorの`JSObject`のメソッドを使う（`org.json`の`optString`とは`null`や数値の扱いが違うため）。

## 3と4の実施

本人の「3と4も実施して」により実施した。

3. **`persistFinish`を名前の付いた段階に分けた。** 保存後のmainの処理から、ウィジェットの書き換え（`updateWidget`）、到着通知（`notifyArrival`）、500ms後の通知の確認と記録（`recordNotified`）を切り出した。保存→資源の解放→ウィジェット→通知→解放の記録→500ms後の確認、という順番は変えていない。停止の判定は要求時の`status`、通知の文面は保存後の`savedStatus`のまま。ウィジェットの失敗で通知を止めない点、各catchの範囲も同じ。
   - 最初の案では、停止の判定を`notifyArrival`の外に出していた。比較の結果、停止の場合に通知の許可の確認（読み取りだけ）が1回減ることが分かったので、判定を関数の中へ戻し、呼び出しまで変更前と同じにした。
4. **小さい整理。** `MagiWidgetStore.read`で`masked()`を1回だけ読む。`MagiWidgetProvider.responsive`の字下げのずれと一時変数をなくし、各分岐から直接返す（同期の範囲は同じ）。
   - `native-widget.js`の`(attempt || 0)`を引数の既定値にする整理は**行っていない**。確認の途中で、`state()`の直後の`sync()`では再試行の上限が効かないことが分かった（下記）。既定値にしても直らず、直すと動作が変わるため、整理とは分けて本人の判断を待つ。

### 見つかった不具合（後で修正済み）

`native-widget.js`の`run(task)`は`tail.then(task)`で直前の処理の結果を`task`へ渡す。`state()`の後に`sync()`を呼ぶと、`sync`の`attempt`にウィジェットの状態のオブジェクトが入り、`(attempt || 0) >= 2`が常にfalseになる。`widget_state_changed`が続く間は上限なく再試行する。模擬のネイティブ応答で、単独の`sync()`は3回で失敗、`state()`の後は6回目の成功まで再試行することを確認した。修正案は`sync: function () { return run(function () { return sync(0); }); }`。

# MAGI 6.7 公開評価（アプリ内のアップデート）

実装済み（2026-10-24）。正本はコード。本人の「コミット、版の更新、APK のビルドと公開まで進めて」により 6.7 / 670 として公開した。

- Android の ☰（チャットの一覧）の下に「アップデートの確認…」を置いた。押すたびに GitHub の最新 Release を確かめ、最新・新しい版あり・確認できない、のどれかを出す。PWA には出さない。
- 新しい版は `MagiUpdatePlugin` が `magi-android.apk` を落とし、Release の資産の `digest`（SHA-256）・パッケージ名・署名証明書・より大きい versionCode がすべて合ったときだけ Android のインストール画面を開く（`REQUEST_INSTALL_PACKAGES`。初回は「この提供元のアプリを許可」の画面）。取得先はこのリポジトリの Release に固定し、画面からは版と SHA-256 だけを受け取る。転送は https の `github.com`・`*.githubusercontent.com` だけ、上限 64MiB。
- digest が無い・プラグインが無いときは、ダウンロードページへの案内だけにする。起動時のお知らせの［ダウンロード］も同じ画面を開く。回答の受信中は始めない。
- 1日1回の自動確認の挙動は変えていない。

- ソースコミット `eb0db0c8`、main への反映とタグ `v6.7` は `94af41e461fbb9c3be32f8fd3a8057815ef1db22`（最新の main をマージ。magi-app 配下は `eb0db0c8` と同一）。Worker の変更は無く、再デプロイしていない。
- [Release v6.7](https://github.com/tk33r1/st/releases/tag/v6.7) を正式公開し Latest にした（draft・prerelease ではない）。
- `magi-android.apk` 3,835,645 bytes、SHA-256 `6c2d939c6b810db85c62795f9de65dcdb15a6551cc6173792abb6a94084f5bc1`。GitHub の API が返す資産の digest、[公式 Android ダウンロード](https://tk.st/magi-app/android/) の実ファイル（HTTP 200・`application/vnd.android.package-archive`）と一致。
- 公開 PWA の `app.js`・`sw.js` はコミットとバイト一致。トップページは `ver 6.7`、`/magi2/versions?format=2` の先頭は 6.7。

## 公開前後の検証

- Node の回帰: `test-magi2.mjs` 362件（SHA-256 の読み取りの新しいテストと版の整合を含む。マージ後のツリーでも成功）。
- 実ブラウザ: `test-magi-native-shell.mjs`（PWA と模擬ネイティブ）。模擬ネイティブで、同じ版は「最新」、新しい版は SHA-256 付きでネイティブへ渡りインストール画面を開いた表示になること、PWA の ☰ に項目が無いことを確かめた。画面のエラー 0、AI への送信 0。
- `npx cap sync android` の後、Android の単体テスト 12件と署名付き release のビルドが成功。`verify-apk.py --commit 94af41e4` で www の資産のバイト一致、6.7 / 670、API 24 / 36、既存の証明書（`0ab1a655…`）、v1 / v2 署名を確認した。`aapt2 dump permissions` で `REQUEST_INSTALL_PACKAGES` が入っていることを確認した。
- GitHub の配布 URL は1回だけ `release-assets.githubusercontent.com`（https）へ転送され、許可した範囲に収まる。

## 0. 実装前の確認（実機）

- 次の操作をそれぞれ3回ずつ行い、回答が最後まで届いたか（画面に戻ったときに完了しているか、`wrangler tail` で Worker が `done` まで進んだか）を記録する。

| 操作 | 合格 |

| 送信直後にホーム画面へ戻り、5分置く | 3回とも完了 |
| 送信直後に画面を消し、5分置く | 3回とも完了 |

## 1. 構文と単体（端末を使わない）

- 構文: `node --check magi-app/www/app.js`。Worker（B2）は `node --check workers/magi2/src/index.js`。
- `node --test .github/scripts/test-magi2.mjs` に足す（既存の全テストも通す）。プラグインは模擬に差し替え、`Capacitor.isNativePlatform()` の真偽の両方で通す。
- 共通: Web・PWA（`Capacitor` が無い）では、どのプラグインも呼ばず、マイクのボタン・設定の画面・共有の札が出ない。
- 「System & Privacy」のアプリだけの段落（APK に同梱）に、AI の会社の名前（OpenAI・DeepSeek・Anthropic・Gemini など）や「3社」が無い（設計§8）。送り先の段落は Worker から出る。
- 共有した資料の題名を TypeSafe AI に送る段落（`requires: ['share']`）は、機能の名前 `share` を持つアプリ（B2 以降）にだけ出て、Web・PWA・それより前の APK には出ない。

### 1.1 B1 履歴

- 移し替え: localStorage の会話（今の会話・保存会話・言語・題名）がファイルへ写り、読み直して一致したときだけ localStorage の項目が消える。
  - 書き込みの失敗・読み直しの不一致では消さず、次の起動でやり直す。その間は localStorage から読める。
  - 壊れた項目（今の `cleanHistory`・`magiCleanItem` で落ちるもの）は今と同じく落とす。
  - 2回目の起動で移し替えを繰り返さない。
- 保存: 書き込みが一時ファイル → 名前の変更の順で、途中で失敗しても前の内容が残る。
- 画像: 同じ画像は1つのファイルになる。会話を消すと、その会話だけが使う画像が消え、ほかの会話が使う画像は残る。
- 全削除・書き出し: 全削除で `magi/` が空になる。書き出しの JSON に全会話が入り、画像の本体が入らない。
- 送信: Worker に送る履歴が今と同じ（元の画像を送らない）。

### 1.2 B2 共有・音声

- 受け取り（模擬の intent）: 文字・URL 入りの文字・画像1枚・画像5枚（4枚と通知）・文字と画像。アプリが閉じていた（起動の intent）・開いていた（`onNewIntent`）、
  画面の準備の前に届いた、の各々。新しい会話になり、入力欄に入るだけで送られない。
- 文字コード: Shift_JIS・EUC-JP・UTF-8 のページ（`Content-Type` の charset あり・`<meta charset>` だけ・どちらも無し）が文字化けせずに抜き出せる。
- URL の条件: `http(s)` 以外・`localhost`・私用の IPv4/IPv6 の直書き・リダイレクト先が私用・4回目のリダイレクトを取りに行かない。
  期限 8秒・2MB を超える本文・HTML 以外で読まず、URL だけ入る。
- 抜き出し: 6000字で切れる。HTML のタグ・スクリプトが入った本文でも、札・全文表示が文字として出る（`textContent`）。
- 札: ×で外れて `shared` を送らない。送ると `shared` が付き、同じ会話の2回目以降の質問にも同じ `shared` が付く（設計§3.3）。保存・復元しても付く。
- Worker の `shared`: 上限（題名 200・URL 2000・本文 6000）を超える・http(s) 以外の URL は 400。制御文字が落ちる。
  3人格・統合・事実の確認の入力に、データとして扱う指示の見出し付きで入る。Jev の分類には本文が入らず、題名だけが `shared_title` として入る。`history_max_chars` と別に数える。
- 音声: 押して開始・再押しで停止。確定した文が入力欄の後ろに足され、送られない。許可を断られたときの案内。
  プラグインに端末の言語が明示して渡る。対応していない言語のときは英語で認識し、知らせが一度だけ出る。

### 1.3 B3 討議の継続

- 送信でサービスが始まり、`done`・エラー・停止・会話の切り替えで止まる（止め忘れが無い）。続けて2回送っても、サービスは1つ。
- 完了の通知: アプリが前面なら出さない、後ろなら出す。エラーなら「受け取れませんでした」。通知のディープリンクの `id` が正しい。
- 常駐の通知の「停止」が、停止ボタンと同じ処理を呼ぶ。
- 通知の許可が無いとき: 会話が止まらず、通知だけ出ない。
- 通知のチャンネルが2つ（討議中・回答の到着）作られる。
- プロセスが無い状態で完了の通知（の模擬の起動リンク）から開くと、その会話が開き「回答を受け取れませんでした」が出る。

### 1.4 B4 ウィジェット

- `MagiWidget.update` が回答の完了・会話の削除・伏せる設定の変更で呼ばれ、`summary` が 120字・改行なし・伏せる設定のときは中身を渡さない。
- ディープリンク: `magi://new`・`magi://voice`・`magi://open?id=` の各々の動き。一覧に無い `id`・壊れたリンクは新しい会話。リンクで送信・削除が起きない。

## 2. 実機の確認

### 2.0 B0

- 計画§0.2 と同じ項目を、配布用の APK で確かめる。前の版の上から入れて、会話の履歴が残る。

### 2.1 B1

- 前の版で会話を 30件以上（画像付きを含む）作ってから上書きで入れ、全部の会話が開け、画像が出る。設定に使っている容量が出る。
- 6MB を超える会話を作り（画像付きの会話を多く）、古い会話が消えない（今の版では消える量）。
- 書き出しを共有メニューで受け取り、JSON を開いて中身を確かめる。全削除で会話が消える。
- APK の `AndroidManifest.xml` が `allowBackup="false"` になっている（`aapt dump xmltree` などで確かめる）。

### 2.2 B2

- Chrome の記事・X の投稿・ギャラリーの写真（1枚・5枚）・メモの文を共有して、入力欄と札に入る。札から本文を読める。送って3人格と統合が資料を踏まえて答える。
- 本文を読めないページ（ログインが要る・PDF・取得が遅い）で「URL だけ送ります」になる。
- 音声で日本語・英語の質問を入れて送れる。マイクの許可を断った後の案内。

### 2.3 B3

- 計画§0.1 と同じ操作を配布用の APK で行い、完了の通知が出て、押すとその会話が開く。
- 常駐の通知の「停止」で止まり、質問が入力欄に戻る。
- Android 13 以上で、通知の許可を断っても会話ができる。

### 2.4 B4

- ウィジェットを置き、2×1・3×2・4×3 に変えて、レイアウトが切り替わり、文字が欠けない。
- 伏せる設定（既定）で「前回の会話（非表示）」、表示にすると題名と結論。MAGI モードの会話で決議が出る。
- 各ボタンで設計§7.4 のとおり開く。アプリが閉じている・開いている・別の会話を開いている、の各状態で。
- 会話を全部消すと空の表示になる。端末の再起動後も表示が残る。

# サイト内検索：Jev の実測（Phase 0・Phase 1）

Phase 1（本番と同じ変換での評価）は末尾の「Phase 1」の章。以下の Phase 0 の章は当時の記録として残す。

実施（2026-10-06）。本番は変更していない。計画は [site-search.md](site-search.md)。

対象は 404 の検索（scope `site`）。`data/site-search.json` のうち、日刊の号を除く35ページを候補にした。

## 結果と判断

- **送り方**：35ページを1回のリクエストにまとめ、判定の基準を付けた問いで送る。精度・速さとも、比べた中で最も良かった。
- **閾値**：初期値は 0.35 にする。0.5 では「バイク事故」→ Motovlog（0.39〜0.41）を落とした。
- **応答時間**：Jev 単体の p95 は255ms。PRD の1.5秒はブラウザから Worker を経由して本文を受け取るまでの条件なので、この実測だけでは合格を判断できない。Jev の待ち時間の上限（本文読み取りを含む2秒）は初期値とし、Phase 1で経路全体を測り直す。
- **費用**：1回あたり入力約1.2万トークン、約 $0.0005。1,000回で約 $0.5。
- **上限**：問いの数の上限は無く、トークン数で決まる（1回6.4万トークン）。35ページなら約5倍の余裕がある。

問い合わせと正解は、API の結果を見る前に Claude が決めた。利用者による確認は受けていない。31件の答えのある問い合わせと8件の答えの無い問い合わせ、計39件の小さな評価なので、Phase 1 で60件以上に増やして確かめ直す。

- いまの検索は、39件中38件が0件だった。当たったのは「QR」だけ。
- 「まとめて・基準あり」を2回実行し、値の差は ±0.04 以内だった。2回目は閾値 0.4 で「バイク事故」（0.39）を落とした。0.35 なら2回とも31件すべてに正解が入り、答えの無いものでは結果を出さなかった。
- 答えの無い問い合わせの最高値は 0.26（「PDFをWordに変換したい」→ ツール一覧）。答えのある問い合わせの正解の最低値は 0.39（「バイク事故」→ Motovlog）。この間に閾値を置く。
- 1件ずつ送る方法は、1位の誤りと、答えの無いものへの結果が増えた。応答も遅い（p50 560ms）。理由は確かめていない（問いでは、どちらの方法でも「ほかの候補は判断に使わない」と指示している）。

## 再現の方法

スクリプトは手元の一時フォルダで実行し、リポジトリには置いていない。条件は次のとおり。

**この実測の入力は、PRD の本番の変換（[site-search.md](site-search.md) 3.3 の `toRankCandidate`）を通していない**。渡す項目は PRD の方をこの実測に合わせて決め直したが、項目の切り方や索引からの取り出し方が本番と同じとは言えない。そのため、ここの精度は送り方と閾値の見当を付けるための参考にとどめ、404 に入れる判断は Phase 1 で本番と同じ変換を通して測り直した結果で行う（同 7.1・7.3。評価セットとスクリプトはリポジトリに置く）。

- モデル：`jev-latest`（応答は `jev-1.13.0`）。キーは `workers/magi2/.dev.vars` の `MAGI_TYPESAFE_API_KEY`。
- 候補1件に渡した項目：
  - 種類・題名・説明（300文字まで）
  - 英語の題名・説明（あれば）
  - ツールはタグとカテゴリー（`tools.json` の題名を使う）
  - ゲームはジャンル
  - 記事はタグ
- 問いの文面と基準は [site-search.md](site-search.md) 3.3 のとおり。

## Phase 1：tune（2026-10-06）

本番と同じ関数（`toRankCandidate`・`rankPayload`・`rankSearch`）で、`.github/scripts/eval-site-rank.mjs --accuracy --set tune --runs 2` を実行した。閾値を選ぶための測定で、合否は別の `final` で決める（設計書 10.4）。

- コミット `dd704559`、revision 1（決める前の設定）、Jev `jev-1.13.0`。
- 索引：`index_hash` `460ead4c…`、`candidate_hash` `72ed536f…`（本番の `site-search.json` と同じ）。
- 評価セット：`.github/site-search/rank-queries.json` の `tune` 40件（答えのある32件、答えの無い8件。英語の画面8件）。正解は Claude が付け、結果を見る前の 2026-10-06 に固定した。本人は確かめていない（PRD 7.1）。
- 失敗・時間切れ・判定の欠けは、どの方式・どの回も0件。Jev 単体は p50 約210ms、p95 約260ms。

### 決めたこと

- **問いの言語**：日本語。基準付きは日英とも上位5件の正解が100%で、答えの無いものへの誤表示が少ない日本語を採った（設計書 3.4 の決め方）。英語の文面は消した。
- **閾値**：0.4。日本語・基準付きは 0.3〜0.6 のどれでも2回とも条件を満たしたので、「正解のページの確率の最低」0.60（site-004「テトリス」）と「答えの無いもので出た最も高い確率」0.23（site-035「PDFをエクセルに変換したい」→ ツール一覧）の両側からの余裕が最も大きい値を選んだ（設計書 10.4 の手順2）。

## Phase 1：final（2026-10-07）

- コミット `39eeea40`（本番の Worker と同じコード。Version `1e06ce40`、本番のログの revision も 2）、Jev `jev-1.13.0`。
- 索引：`candidate_hash` `72ed536f…`。本番の `https://tk.st/data/site-search.json` から作ったものと一致（`--hash`）。
- 評価セット：`final` 40件（答えのある32件、答えの無い8件。英語の画面8件）。`tune` と同じく Claude が付け、2026-10-06 に固定した正解。

- 2回を通して、正解のページの確率の最低は 0.61、答えの無いもので出た最も高い確率は 0.16（site-075「PDFに電子署名したい」→ ツール一覧）。判定の欠けは0件。Jev 単体は p50 約205ms、p95 約240ms。
- 2回で表示ページが変わったのは4件で、どれも正解には関係しない。site-043「GIF」・site-049「SVGファイルを軽くしたい」・site-062「split a pdf」は、ツール一覧の確率が 0.36〜0.43 と閾値の際にあり、片方の回だけに出た。site-044「ゲーム」は、0.4 を超えるゲームが5件より多く、上位5件に入るものが入れ替わった。順位だけの変化は2件（site-053・site-066。どちらもテトリスの作品どうし）。
- 精度の条件は2回とも満たした。合否はこのあとブラウザからの応答時間（T3.7）と合わせて決める。
- 注意：`tune`・`final` ともほぼ満点で、評価セット（Claude が作った）が Jev にとって易しかった可能性がある。実際の検索語での判定は、公開後の見守り（T5.7）で確かめる。

# サイト内検索 Phase 3 実装計画書

実装・公開済み（2026-10-10）。2026-10-09の本人のレビューで範囲を「日刊2誌の②」に絞った。同範囲の正本はコード。T01〜T14を完了し、両誌の②を本番で有効化した。最新号の精度評価・媒体別の速度・切断・停止復帰・本番の計測を確認。公開の版と証跡は[完了記録](site-search-phase3-completion.md)。Safari・iOS・Androidの実機確認は未実施として分けて記録した。

要件は [PRD](site-search-phase3-prd.md)、作り方は [設計書](site-search-phase3-design.md)、合否は [検証計画書](site-search-phase3-verification.md)。本書は作業の順番・依存・完了条件と進み具合だけを管理する。Phase 0〜2 の T 番号と区別するため `P3-Txx` を使う。

## 1. 進め方

- 作業はコーディングエージェント（Claude Code・Codex）が進め、仕様の確認と公開の判断は本人が行う。実 API の測定は、評価セットを固定し、回数と費用の見積もりを示してから行う。
- Phase 2 の合格記録を Phase 3 の合格として流用しない。
- 1作業1コミットを基本にする。サイトに出る変更は公開単位がそろってから main に入れる。push は本人の指示に従う。
- 日刊の bot の最新号を取り込んでから再生成する。再生成の直後に号が増えたら取り直す。共通 JS の参照の更新と、それを読む HTML は同じ push で出す。

## 4. 検証と実行上の注意

手元の検証は模擬の上流で行う。`test-magi2.mjs`・`test-site-search-index.py`・`test-daily-news.py`・`test-site-search-ui.mjs` を使い、Phase 3 の抜けを足す。実 API を呼ぶ CLI は、scope・回数・対象の索引を明示できるようにする。

実測の前に、モデル・契約・単価を設定と公式資料で確かめる。キーや検索語を含む生の記録は `workers/.wrangler/`（追跡しない）だけに置く。合格記録は媒体ごとに [検証計画書](site-search-phase3-verification.md) からたどれるようにする。
